### FIX (PATCH)

#### OV (`ov/views.py`, `docs/ov/openapi.yaml`, `ov/tests.py` — `GET /ov/contract-detail/` responds directly again)
    - `GET /ov/contract-detail/?contract_token=<token>` returns `200` with the contract detail (same `ContractFullDetail` schema as `/ov/contract/{token}/`) instead of redirecting with `302`.
    - The token may contain a slash (`/`), which a `<str:token>` route cannot resolve: it used to raise `NoReverseMatch` (`500`). The contract is now looked up by query (`Contract.token`).
    - The `request` is passed to the serializer so the optional `dni` query param keeps unmasking the IBAN and driving `is_account_holder`. `400` when the parameter is missing; `404` when the contract does not exist.
    - `docs/ov/openapi.yaml`: documents `200` (`ContractFullDetail`) and `404` instead of the `302`.
    - Tests in `ov/tests.py` (`ContractOVViewTests`): slash token, plain token, unknown token, missing parameter and processing of extra query params without redirect.
