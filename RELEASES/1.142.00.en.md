On 21-10 delinquency management changes its internal API in an incompatible way (PR #97). It counts as `FEAT` and not as `BREAKING` because only the frontend uses it, and the frontend is updated in the same release (see Notes).

## Highlights

- Home page with a per-user customizable dashboard and a new task calendar with recurring tasks and a daily summary by email.
- Configurable accounting (accounting rates, extra lines, balance movements) and new asynchronous delinquency management (provisions and bad debts).
- Supply cuts: protection of vulnerable people, a dedicated communication flow, and the people excluded from each communication with the reason.
- Communication SMS sent through the Broadcaster, to mobile phones only.
- Contract debt detail with creation of grouped payments.
- New reports: «Billing dashboard» and «Billing summary by rate, tier and social rate».
- Security: rate and adjustment formulas evaluated without `eval`, API errors without internal details, logs without personal data, and exports protected against formula injection.

## Notes

- **Deploy backend and frontend together.** Many changes depend on both sides: #22, #31, #34, #49, #55, #60, #61, #64, #67, #70, #73, #90, #97, #101, #103, #109, #110, #113 and #117.
- **Migrations** (`migrate`):
  - billing `0321`–`0326`
  - communication `0033`–`0035`
  - coredata `0137`–`0144` (there are repeated numbers, resolved with merge migrations)
  - dashboard `0001` (new app)
  - notification `0025`
  - pricing `0120`–`0132`
  - service `0135`
  - statistics `0046`–`0048`
  - There are data migrations: `communication.0034`, `coredata.0138/0139/0143`, `billing.0326`, `pricing.0132` and `statistics.0047`. `billing.0324` drops the `start_date` columns from `CommitmentDeposit` and `PaymentCommitment`.
- **Opscripts** (`manage.py run_pending_scripts`):
  - `coredata/0003` and then `coredata/0004` (street numbers). Both list cases to review by hand.
  - `contract/0004` (applicant of requests).
  - `statistics/0003` (new report).
  - `billing/0008`: deletes duplicated invoice PDFs from disk. Beforehand, run `manage.py clean_duplicated_invoice_pdfs --dry-run` and back up `uploads/billing/invoices`.
- **New environment variables** (PR #100): `BROADCASTER_API_TOKEN`, which is **required** to send SMS, and the optional `BROADCASTER_API_URL`, `BROADCASTER_TIMEOUT_SECONDS`, `BROADCASTER_USER_AGENT`, `BROADCASTER_CHANNEL`, `BROADCASTER_TOPIC`, `BROADCASTER_TEMPLATE_CODE`, `BROADCASTER_TEMPLATE_NAME` and `BROADCASTER_TEMPLATE_BODY`. They are not in `.env.example`.
- **New ConfigProject entries:**
  - `order_reason_contract_termination`, `order_reason_contract_activation`, `order_reason_new_connection_request` and `order_reason_customer_supply_cut` (#34). Check on each installation that the reasons exist and have linked order types.
  - `BAIL_RETURN_INVOICE_DISABLED` (#96, default `false`).
  - `aca_tram_members_variable_token` (#114, default `ACA-TRAM-MEMBRES`). The exact token is now required: review `/settings/config_aca/` wherever a different one is used.
  - `attach_extra_docs_in_claims` (#115, default `true`).
  - `order_type_change_meter_tokens` (#60, optional, not created).
- **Celery:** the `beat_schedule` changes (#60): `notify_today_tasks`, `generate_recurring_tasks` and `send_daily_tasks_email`. The beat and the workers must be restarted.
- **Behavior changes:**
  - #97: `POST /api/billing/get-deliquency/` is asynchronous and returns `{"task_id"}`.
  - #61: writing to the ConfigProject with a user other than `customers` returns `403`. This includes the old `config_aca/index_prev` page and external scripts.
  - #87/#89/#91: API errors return a generic message instead of the exception text. Keys and HTTP codes are kept.
  - #118/#121: rate, tier and adjustment formulas only accept a closed list of operations and functions. Review existing formulas before deploying.
  - #108: bulk payment excludes SEPA, balance, online POS and quotes.
  - #67: an already created cut does not allow changing its points.
  - #70: landline phones cannot be added as SMS phone. `manage.py check_sms_phones` can be used to detect existing ones.
- **Transfer files** (#62, #64): the pain.001 XML for returns changes. Generate a test one, validate it with the new button and confirm the bank accepts it.
- **GMAO** (#93): the consumer accepts the `order.created` event. To take advantage of it, the GMAO must publish it.
- **Images:** with `CUSTOMERS_VERSION=v1.142.00` in `.env`, `docker compose pull && docker compose up -d`, and then `docker compose exec backend python manage.py migrate --noinput`.
