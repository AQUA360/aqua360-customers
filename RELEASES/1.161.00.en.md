## Highlights

- Security audit: login attempt limit, read permissions on every view, validated passwords, protected images, SFTP in the document manager, non-root containers and a startup that requires a secure `SECRET_KEY`.
- Only the `customers` superuser manages users and groups; other administrators can view them but not change them.
- Multi-company billers: one billing run for each water supply company.
- Payments marked for remittance, configurable SEPA receipt concept and company account check on transfer remittances.
- Billing PDFs generated in parallel and ACA Declaration without running out of memory; agricultural consumption in the ACA Declaration and the FACTDETA.
- Reports in PDF, as well as Excel.
- Outgoing webhooks to notify an external system of contracts, terminations and invoices (disabled by default).
- Virtual Office: contracts with an active VO, address and person invoice endpoints, and invoices with a future date hidden.
- Meter change history of the supply point.

## Notes

- **Deploy backend and frontend together.**
- **Before deploying, on existing installations:**
  - **Non-root containers (#369, #374):** the backend runs as user `app` (uid 1001). In the stack folder, once: `chown -R 1001 docker-data/media docker-data/static`. Without it the backend does not start (message in the log). Installations updated through HelpAsset do it with the update script.
  - **`SECRET_KEY` required (#386):** without `SECRET_KEY` (or with the example one) the backend and `docker compose` do not start. `DEBUG` is now `False` by default.
  - **The frontend no longer reads the whole `.env` (#374):** it only gets the variables passed by `docker-compose.yml` (`NUXT_PUBLIC_*`, `NUXT_EXTERNAL_GOT`, `VERIFACTU_ENABLED`, `TZ`, `NODE_OPTIONS`). Installations with their own `docker-compose` must review it.
- **New dependencies:** backend `django-axes`, `paramiko` (and `bcrypt`, `PyNaCl`, `invoke`); Django 5.0 → 5.2, DRF 3.15 → 3.18, `PyPDF2` removed. Frontend: `xlsx` 0.20.3 (official package), `lodash` declared, `quill` removed. They come with the images.
- **Migrations** (`migrate`):
  - billing `0346`–`0351`
  - communication `0041`
  - contract `0251`
  - coredata `0158`, `0159`
  - documentmanager `0019` (choices only)
  - integrations `0007`
  - pricing `0140`, `0141`
  - service `0146`
  - statistics `0058`–`0063` (two `0058`; `0060` merges them)
  - Data migrations:
    - `billing.0351` creates the `billing_pdf_parallel_workers` ConfigProject (see below).
    - `coredata.0158` marks the `users` permission so that only the superuser can change it.
- **Opscripts** (`manage.py run_pending_scripts`):
  - `auth/0001_revoke_user_management_write_perms`: removes user and group write permissions from groups (#384).
  - `auth/0002_keep_only_customers_superuser`: **leaves `customers` as the only superuser; the other superusers become administrators** (#384).
  - `billing/0009_remove_invoice_chart_files`: deletes the consumption chart images stored separately (#393).
  - `billing/0009` and `0010_deactivate_duplicate_bail_piggy_movements`: deactivate duplicate piggy bank movements of deposit refunds (#424). There are two `0009` in billing; the runner records them by name and all of them run.
  - `coredata/0006_fill_person_bank_origin`: `OV` origin for IBANs set from the VO; the rest stay `HIST` (#423).
  - `service/0003_backfill_meter_history_from_logs`: fills the meter change history from existing logs (#396).
  - `statistics/0007_enable_pdf_export_reports`: enables PDF export on reports (#349).
- **New ConfigProject:**
  - `billing_pdf_parallel_workers` (default `4`): parallel subtasks to generate the billing PDFs (#394).
  - `sepa_concept_fields`: created when the SEPA receipt concept settings are saved; until then the concept carries all fields (#383).
- **New environment variables** (all optional):
  - `SFTP_HOST`, `SFTP_PORT`, `SFTP_USER`, `SFTP_PASSWORD`, `SFTP_KEY_FILE`, `SFTP_KNOWN_HOSTS`: replace `FTP_*`; only needed with `DOCUMENT_MANAGER_*=sftp`, and the `known_hosts` must be mounted in the container (#378). No installation used FTP.
  - `WEBHOOKS_ENABLED` (default `False`), `WEBHOOKS_URL`, `WEBHOOKS_SECRET` (#402).
  - `OV_SYNC_ENABLED` (default `False`), `OV_SYNC_HOUR`, `OV_SYNC_MINUTE`, `OV_API_BASE_URL`, `OV_API_KEY`, `OV_API_TIMEOUT`, `OV_ACTIVE_CONTRACTS_ENDPOINT`: daily contract sync with the VO (#358).
  - `GMAO_USER_USERNAME`, `GMAO_USER_PASSWORD`, `GMAO_USER_EMAIL`: GMAO user (`get_or_create_gmao_user` command) (#382).
  - `CELERY_WORKER_CONCURRENCY` (default, one per CPU) and `CELERY_WORKER_MAX_MEMORY_PER_CHILD` (default 2 GB) (#394).
  - `DB_SYNC_CONTROL_DIR` and the `docker-data/sync-control` volume: test servers only (#426).
  - `CUSTOMERS_GIT_DIR`: only to build images on the server from a worktree (#353).
- **Behaviour changes:**
  - #384: only `customers` can create or change users, groups and permissions.
  - #356, #363: 5 failed attempts lock the user for 15 minutes (API and `/admin/`) and there is a limit of 10 attempts per minute per IP. `NUM_PROXIES=2` assumes Cloudflare + nginx in front of the backend.
  - #381, #405: new user and operator passwords must pass Django's validators (at least 8 characters and a number).
  - #385, #399, #407: views require the `view_*` permission to read; users who only had write permissions, or none, no longer see them. Groups must be reviewed.
  - #383: the SEPA receipt concept changes: it carries the contract, invoice, amount, consumption and supply point.
  - #429: invoices of contracts already terminated when the billing run is processed are excluded.
  - #422: the VO does not return invoices with a future issue date.
  - #393: images outside the logo and exploitation folders require authentication.
  - #420: daily documents without data are cancelled.
- **Images:** with `CUSTOMERS_VERSION=v1.161.00` in `.env`, `docker compose pull && docker compose up -d`, then `docker compose exec backend python manage.py migrate --noinput` and `docker compose exec backend python manage.py run_pending_scripts`.
