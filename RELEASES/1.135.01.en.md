# Product release 1.135.01 — 16-10-2026

| Component | Version |
|---|---|
| Backend | 1.135.00 |
| Frontend | 1.123.00 |
| Tag | v1.135.01 |

Product PATCH bump with no component changes: Docker and deployment only (PR #25). The application code is the same as `v1.135.00`.

## Highlights

- Backend and frontend images built on GitHub when a release is published and pushed to `ghcr.io/aqua360/aqua360-customers-backend` and `-frontend`, tagged with the release and the commit. Servers pull them instead of building.
- `docker-compose.yml`: the image version is chosen with `CUSTOMERS_VERSION` in `.env`. Without it, the server builds as before, with one image per stack (`local-<stack>`).
- `gmao-consumer` optional per customer with the `gmao` profile (`COMPOSE_PROFILES=gmao`), and a health check without `ps`.

## Component notes

- Backend: no changes since [`1.135.00`](../backend/CHANGELOGS/RELEASES/1.135.00.en.md).
- Frontend: no changes since [`1.123.00`](../frontend/CHANGELOGS/RELEASES/1.123.00.en.md).

## Notes

- Baseline: product `1.135.00` (14-10-2026).
- No migrations.
- **GMAO:** stacks that use it must have `COMPOSE_PROFILES=gmao` in `.env` (already set in Argentona and AVSA). On the others, the existing `gmao-consumer` container must be removed once (`docker compose rm -sf gmao-consumer`): `up` does not remove it.
- **Images:** with `CUSTOMERS_VERSION=v1.135.01` in `.env`, `docker compose pull && docker compose up -d` deploys this version without building. HelpAsset does it automatically when updating.
