## Highlights

- Custom reports with read-only SQL queries, pivot table and export to CSV or Excel.
- Odoo integration: batch submissions with tracking and resubmission, and a profile for Odoo Enterprise SaaS.
- FACTDETA with the ACA 2026 format, freezing of the already submitted months of the ACA Declaration and a file analysis tool.
- Bulk meter change from a file, with preview.
- Routes: add all the numbers of a street, import routes from Excel or CSV and own route per supply point.
- Billings and reading batches filtered by exploitation, with the numbers fixed when they are closed.
- Billing communications with the Virtual Office link, grouped sending of invoices by email and separation of 2-page invoices for printing.
- Virtual Office: termination and name change procedures. GMAO: property search and more data in the order creation event.

## Notes

- **Deploy backend and frontend together.** Many PRs touch both sides (#198, #219, #221, #227, #246, #250, #253, #257…).
- **New dependencies (backend):** `django-sql-explorer`, with `django-appconf` and `django-cryptography-django5` (#221), and `xlrd` (#261). The new image is required.
- **Migrations** (`migrate`):
  - billing `0334`–`0338` (`0338` merges the two `0337`)
  - communication `0038`–`0039`
  - contract `0249`
  - coredata `0152`–`0154`
  - integrations `0002`–`0006`
  - notification `0028`
  - pricing `0133`–`0138`
  - service `0140`–`0144`
  - statistics `0051`, `0052` and `0056`
  - those of the `explorer` app (django-sql-explorer)
  - There are data migrations:
    - `billing.0337` assigns the exploitation to the billers and reading batches when it is unambiguous. Those with two are left without an exploitation and **do not show up with an exploitation filter active**: it must be assigned from the admin (#253).
    - `service.0141` fully protects the GIS Water cuts that had already been modified by hand in Customers (#203).
    - `communication.0039` creates the "SEPA return" origin and moves to it the unpaid debt templates that have "return" in the name (#243).
    - `statistics.0051` creates the FACTDETA report.
    - `coredata.0152`–`0154` and `service.0140` create ConfigProject (see below).
  - `billing.0336` creates an index on the invoices table: it is fast, but blocks writes to invoices while it is being created.
- **Opscripts** (`manage.py run_pending_scripts`):
  - `service/0001`: loads the building type and representative type catalogues of the service connection request (only the missing tokens).
  - `statistics/0004`: main permission of the custom reports (`view_custom_report`, `change_custom_report`).
  - `statistics/0005` and `0006`: debt and balance report per contract at a date.
- **New ConfigProject:**
  - `ODOO_ENABLED` (default `false`): shows the batch submissions screen (#198).
  - `send_batch_status_pending_token`, `send_batch_status_processing_token` and `send_batch_status_finalized_token`: submission batch statuses.
  - `send_batch_provider_odoo_token`: **not created by any migration**; it must be created on installations that send to Odoo.
  - `giswater_supply_cut_sync_enabled` (default `false`): synchronisation button in the cuts list (#200).
  - `leak_estimate_years` (default `2`) and `leak_estimate_statistic` (`mean` or `max`, default `mean`): optional, for the leak proposal (#231).
  - The name of `contract_domestic_use_type_token` indicates that it accepts several values separated by `|` (#233).
- **New environment variables:**
  - `CUSTOM_REPORTS_DATABASE_USER` and `CUSTOM_REPORTS_DATABASE_PASSWORD`: read-only role of the custom reports; created with `manage.py setup_custom_reports_role`. Without this role, no reports are run. Optional: `CUSTOM_REPORTS_STATEMENT_TIMEOUT` (60 s), `CUSTOM_REPORTS_MAX_ROWS` (5.000) and `CUSTOM_REPORTS_EXPORT_MAX_ROWS` (200.000) (#221).
  - `ODOO_TRANSPORT` (`fastapi` by default, `json2` for Odoo Enterprise SaaS) and `ODOO_INBOUND_BEARER_TOKEN`, the token Odoo sends in the batch callback (also read from `ODOO_INBOUND_API_KEY`) (#198, #215).
  - `GISWATER_SYNC_SUPPLY_CUTS_ENABLED` (default `False`) and `GISWATER_SYNC_SUPPLY_CUTS_MINUTES` (default `60`): periodic synchronisation of GIS Water cuts (#205).
- **Celery:** with `GISWATER_SYNC_SUPPLY_CUTS_ENABLED=True`, the beat adds `sync-giswater-supply-cuts`. Restart the workers and beat.
- **New management commands:**
  - `setup_custom_reports_role`: creates the PostgreSQL role of the custom reports (#221).
  - `aca_freeze_declaration`: freezes a submitted month of the ACA Declaration (without `--commit` it only shows it) (#255).
  - `factdeta_analyze`: analyses FACTDETA files (#212).
  - `watchdog_fix_termination_used_aca`: fixes the ACA use of termination invoices (with `--dry-run`) (#254).
  - `push_invoice_batch_to_odoo`, `push_payment_movement_batch_to_odoo` and `push_commitment_deposit_batch_to_odoo` (#198).
  - `reconcile_finished_estimation`: cleans up the old estimation of a reading batch once it is confirmed to have finished (#246).
- **Behaviour changes:**
  - #253: billings, reading batches, SEPA remittances, document downloads and consumption management only show the active exploitation's data.
  - #257: a supply point can have its own route, different from the property's; batches, readings, billing and LecturApp use the point's.
  - #219: in link mode, the invoice is not attached to the email (it is still sent by letter).
  - #211: orders in progress, pending validation, closed or with reports cannot be deleted; when one is deleted, `order.deleted` is published to RabbitMQ.
  - #213, #218: the `order.created` event carries `supply_point_meter_caliber` and `created_by` in `additional_info`.
  - #239: the invoice period comes from the readings, and may change compared with invoices generated before.
  - #226: in the Virtual Office API, the invoice detail calculates the period with the issue date and the days between readings, and the procedure tariffs only include the contract ones.
  - #251, #223: new endpoints `POST /ov/procedures/contract-termination/`, `POST /ov/procedures/contract-change/`, `GET /ov/dictionary/contract-request-types/` and `GET /gmao/v1/properties/?search=`.
  - #228: installations with the ACA package already loaded have been fixed separately in the database; the package change only affects new loads.
- **Images:** with `CUSTOMERS_VERSION=v1.152.00` in `.env`, `docker compose pull && docker compose up -d`, then `docker compose exec backend python manage.py migrate --noinput` and `docker compose exec backend python manage.py run_pending_scripts`.
