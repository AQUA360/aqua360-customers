El 21-10 la gestión de morosidad cambia de forma incompatible su API interna (PR #97). Se cuenta como `FEAT` y no como `BREAKING` porque solo la usa el frontend, que se actualiza en la misma release (véase Observaciones).

## Highlights

- Página de inicio con dashboard personalizable por usuario y nuevo calendario de tareas con tareas recurrentes y resumen diario por correo.
- Contabilidad configurable (tarifas contables, líneas extra, movimientos de saldo) y nueva gestión de morosidad asíncrona (dotación e incobrables).
- Cortes de suministro: protección de personas vulnerables, flujo de comunicación propio y personas excluidas de cada comunicación con el motivo.
- SMS de las comunicaciones enviados por el Broadcaster, solo a móviles.
- Detalle de la deuda del contrato con creación de pagos agrupados.
- Nuevos informes: «Dashboard de facturación» y «Resumen de facturación por tarifa, tramo y tarifa social».
- Seguridad: fórmulas de tarifas y ajustes evaluadas sin `eval`, errores de la API sin detalles internos, logs sin datos personales y exportaciones protegidas contra inyección de fórmulas.

## Observaciones

- **Desplegar backend y frontend juntos.** Muchos cambios dependen de los dos lados: #22, #31, #34, #49, #55, #60, #61, #64, #67, #70, #73, #90, #97, #101, #103, #109, #110, #113 y #117.
- **Migraciones** (`migrate`):
  - billing `0321`–`0326`
  - communication `0033`–`0035`
  - coredata `0137`–`0144` (hay números repetidos, resueltos con migraciones de merge)
  - dashboard `0001` (app nueva)
  - notification `0025`
  - pricing `0120`–`0132`
  - service `0135`
  - statistics `0046`–`0048`
  - Hay migraciones de datos: `communication.0034`, `coredata.0138/0139/0143`, `billing.0326`, `pricing.0132` y `statistics.0047`. La `billing.0324` elimina las columnas `start_date` de `CommitmentDeposit` y `PaymentCommitment`.
- **Opscripts** (`manage.py run_pending_scripts`):
  - `coredata/0003` y después `coredata/0004` (números de calle). Ambos listan casos para revisar a mano.
  - `contract/0004` (solicitante de las solicitudes).
  - `statistics/0003` (nuevo informe).
  - `billing/0008`: borra los PDF de factura duplicados del disco. Antes, ejecutar `manage.py clean_duplicated_invoice_pdfs --dry-run` y hacer copia de `uploads/billing/invoices`.
- **Variables de entorno nuevas** (PR #100): `BROADCASTER_API_TOKEN`, que es **obligatoria** para enviar SMS, y las opcionales `BROADCASTER_API_URL`, `BROADCASTER_TIMEOUT_SECONDS`, `BROADCASTER_USER_AGENT`, `BROADCASTER_CHANNEL`, `BROADCASTER_TOPIC`, `BROADCASTER_TEMPLATE_CODE`, `BROADCASTER_TEMPLATE_NAME` y `BROADCASTER_TEMPLATE_BODY`. No están en el `.env.example`.
- **ConfigProject nuevos:**
  - `order_reason_contract_termination`, `order_reason_contract_activation`, `order_reason_new_connection_request` y `order_reason_customer_supply_cut` (#34). Comprobar en cada instalación que los motivos existen y tienen tipos de orden vinculados.
  - `BAIL_RETURN_INVOICE_DISABLED` (#96, por defecto `false`).
  - `aca_tram_members_variable_token` (#114, por defecto `ACA-TRAM-MEMBRES`). Ahora hace falta el token exacto: revisar `/settings/config_aca/` donde se use otro.
  - `attach_extra_docs_in_claims` (#115, por defecto `true`).
  - `order_type_change_meter_tokens` (#60, opcional, no se crea).
- **Celery:** cambia el `beat_schedule` (#60): `notify_today_tasks`, `generate_recurring_tasks` y `send_daily_tasks_email`. Hay que reiniciar el beat y los workers.
- **Cambios de comportamiento:**
  - #97: `POST /api/billing/get-deliquency/` es asíncrono y devuelve `{"task_id"}`.
  - #61: escribir en el ConfigProject con un usuario que no sea `customers` da `403`. Incluye la página antigua `config_aca/index_prev` y los scripts externos.
  - #87/#89/#91: los errores de la API devuelven un mensaje genérico en lugar del texto de la excepción. Las claves y los códigos HTTP se mantienen.
  - #118/#121: las fórmulas de tarifas, tramos y ajustes solo admiten una lista cerrada de operaciones y funciones. Revisar las fórmulas existentes antes de desplegar.
  - #108: el pago masivo excluye SEPA, saldo, TPV online y los presupuestos.
  - #67: un corte ya creado no admite cambiar sus puntos.
  - #70: no se pueden añadir teléfonos fijos como teléfono SMS. Se puede usar `manage.py check_sms_phones` para detectar los existentes.
- **Ficheros de transferencias** (#62, #64): el XML pain.001 de las devoluciones cambia. Generar uno de prueba, validarlo con el nuevo botón y confirmar que el banco lo acepta.
- **GMAO** (#93): el consumer acepta el evento `order.created`. Para aprovecharlo, el GMAO lo tiene que publicar.
- **Imágenes:** con `CUSTOMERS_VERSION=v1.142.00` en el `.env`, `docker compose pull && docker compose up -d`, y después `docker compose exec backend python manage.py migrate --noinput`.
