## Highlights

- Linked readings (`copied_from`): editing one updates the whole group, with an on-screen warning
- Configurable company accounts for refund transfers (pain.001), independent from collection remittances
- Smart Metering readings loaded from Enter readings, into a readings document with a result Excel and a single load per date (no longer done from the batch)
- Bulk supply cut planning (by contract, supply point or street) with preview and conflicts
- Per-email SMTP password for each company email, encrypted
- Finish the termination from the new contract and change of name, with a «no invoice» option
- Selectable billing template when sending invoices
- Soft delete of cancelled communications and processes
- Full bank account editing with the same IBAN, and default ID number for the holder
- Single «Bonuses and variables» tab in the contract
- OV: English keys, SEPA mandate upload, direct debit cancellation, `contact-data`, NIC lookup and invoice ZIP
- Invoice PDF: biller period and web QR
- Fixes: minimum number of people for the ACA bracket extension bonus (PA-49), supply point status after a termination, meter change dates, readings at 0 being overwritten, issuing company of the e-invoice, ACA summary, non-billable contracts

## Notes

- Baseline: product `1.133.01` (09-10-2026), backend `1.133.01`, frontend `1.121.00`.
- **Migrations:** `billing.0322`, `service.0131`, `service.0132`, `service.0134` and `coredata.0137`. Run `migrate` when deploying.
- **New environment variable (optional):** `SMTP_PASSWORD_ENCRYPTION_KEY`. For each installation that wants per-email SMTP passwords:
  1. Generate a key and keep a copy somewhere safe: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`
  2. Add `SMTP_PASSWORD_ENCRYPTION_KEY=<key>` to the backend `.env`.
  3. Run `migrate` and restart the backend and the Celery workers.
  4. From the settings screen, save the passwords of the emails that use a different one from the general password.
  Without the key everything works as before (`EMAIL_HOST_PASSWORD`), but passwords cannot be saved.
- **New `ConfigProject`:** `aca_tram_min_persons` (default `4`), only with `uses_aca`.
- **Opscript:** `contract/0003_fix_pending_bails` fixes the deposits left pending when contracts were terminated.
- **Files out of the repository:** `*_personalized*` customizations, `celerybeat-schedule` and the Odoo exports are no longer tracked. On pull, Git deletes them from the working copy: back them up first on the servers that use them.
- Backend and frontend must be deployed together (several API changes with matching UI). In particular, the batch Smart Metering actions (`reading-batch-summary`) have been removed and moved to `reading-document`.
