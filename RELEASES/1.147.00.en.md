## Highlights

- Negative invoices in transfer remittances, and settlement of negative payments into the customer balance.
- Smart Metering settings screen with connection tests and reading queries.
- Barcode suffix per company bank account.
- Change histories and automatic processes record the real user who makes the change or launches the task.
- Unpaid debt export with the holder's tax ID and the detail of the claimed invoices.
- Virtual Office: contract request status and structured property addresses.

## Notes

- **Deploy backend and frontend together.** Several PRs touch both sides (#178, #181, #184, #187, #189, #191).
- **Migrations** (`migrate`):
  - billing `0333`
  - service `0139`
  - There are data migrations:
    - `service.0139` copies the global `reference_suffix_barcode_token` suffix to every existing bank account, if it is a valid three-digit value.
- **Opscripts:** none new.
- **ConfigProject:** none new.
  - `reference_suffix_barcode_token` is only kept as the default for accounts without their own suffix (#187).
  - The Smart Metering screen only shows if `smart_metering_authentication_token` has a value (#184).
- **Celery:** tasks carry the user who queued them (#181). Restart the workers and beat. Tasks queued before the deployment run without a user.
- **Behaviour changes:**
  - #190: in the Virtual Office API, `POST /ov/create-reading/` takes the meter **code** in the `meter` field, not the token, and `meter_serial_number` is always the meter code. New endpoint `GET /ov/procedures/contract/<token>/`.
  - #187: saving a bank account's suffix no longer changes the other accounts' suffix or the global ConfigProject.
  - #181: changes without a user are no longer attributed to the first user in the DB. `order.middleware.CurrentUserMiddleware` is removed (the module re-exports the `contract.middleware` functions).
  - #188: claim letters may use a different address than those generated before.
- **Environment variables:** none new.
- **Images:** with `CUSTOMERS_VERSION=v1.147.00` in `.env`, `docker compose pull && docker compose up -d`, then `docker compose exec backend python manage.py migrate --noinput`.
