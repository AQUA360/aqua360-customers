## Highlights

- Facturas negativas en las remesas de transferencia y liquidación de pagos negativos en el saldo del cliente.
- Pantalla de configuración de Smart Metering con pruebas de conexión y consulta de lecturas.
- Sufijo del código de barras propio de cada cuenta bancaria de la empresa.
- Historiales y procesos automáticos con el usuario real que hace el cambio o lanza la tarea.
- Exportación de impagados con el NIF del titular y el detalle de las facturas reclamadas.
- Oficina Virtual: estado de las solicitudes de contrato y direcciones desglosadas de los inmuebles.

## Observaciones

- **Desplegar backend y frontend juntos.** Varias PR tocan los dos lados (#178, #181, #184, #187, #189, #191).
- **Migraciones** (`migrate`):
  - billing `0333`
  - service `0139`
  - Hay migraciones de datos:
    - `service.0139` copia el sufijo global `reference_suffix_barcode_token` a todas las cuentas bancarias existentes, si es un valor válido de tres dígitos.
- **Opscripts:** ninguno nuevo.
- **ConfigProject:** ninguno nuevo.
  - `reference_suffix_barcode_token` queda solo como valor por defecto de las cuentas sin sufijo propio (#187).
  - La pantalla de Smart Metering solo aparece si `smart_metering_authentication_token` tiene valor (#184).
- **Celery:** las tareas llevan el usuario que las ha encolado (#181). Hay que reiniciar los workers y el beat. Las tareas encoladas antes del despliegue se ejecutan sin usuario.
- **Cambios de comportamiento:**
  - #190: en la API de la Oficina Virtual, `POST /ov/create-reading/` recibe el **código** del contador en el campo `meter`, no el token, y `meter_serial_number` es siempre el código del contador. Nuevo endpoint `GET /ov/procedures/contract/<token>/`.
  - #187: guardar el sufijo de una cuenta bancaria ya no cambia el del resto ni el ConfigProject global.
  - #181: los cambios sin usuario ya no se atribuyen al primer usuario de la BD. Se elimina `order.middleware.CurrentUserMiddleware` (el módulo reexporta las funciones de `contract.middleware`).
  - #188: las cartas de reclamación pueden cambiar de dirección respecto a las generadas antes.
- **Variables de entorno:** ninguna nueva.
- **Imágenes:** con `CUSTOMERS_VERSION=v1.147.00` en el `.env`, `docker compose pull && docker compose up -d`, y después `docker compose exec backend python manage.py migrate --noinput`.
